## 一、用户洞察

### 1.1 目标用户

PaperPilot 面向**个人科研工作者与小团队实验室**——研究生、博后、课题组成员，以及需要管理和阅读学术 PDF 的从业者。

### 1.2 核心痛点

| 痛点 | 现状 |
|------|------|
| **论文积灰** | PDF 堆在本地文件夹里，查找困难，阅读零散，无法快速定位结论与数据 |
| **跨文献对比费时** | 需要手动在多篇论文之间反复切换、标记、比对共同点和差异 |
| **笔记与原文脱节** | 传统笔记工具无法将批注关联到原文段落，事后回溯成本高 |
| **协作但互不干扰** | 同一课题组多人阅读论文，需要各自私有、不互相暴露内容 |
| **现有产品门槛高** | 企业级知识库系统部署复杂、价格高、功能冗余，个人用不起也不需要 |

### 1.3 用户场景

1. **研究生日常阅读**：上传导师分配的 5 篇论文，按课题建库，快速提问「这篇方法的关键创新是什么？」。
2. **文献综述准备**：将同一主题的 10+ 篇论文入库，提问「这些论文的共同研究方法是什么？有何差异？」，系统以表格对比呈现。
3. **组会汇报备稿**：对库内论文追问实验设置、数据集、指标，快速梳理要讲的要点。
4. **多方向管理**：按「信号处理」「深度学习」「临床试验」等方向分建知识库，提问时勾选相关库，互不干扰。

## 二、方案设计

### 2.1 产品定位

> **个人科研文献知识库**——把 PDF 收进自己的私人书房，用自然语言与文献对话。

核心原则：
- **私有优先**：账号隔离，每个用户只能看到自己的内容
- **原文为据**：回答必须有库内检索证据支撑，证据不足如实说明，不硬编
- **轻量可用**：打开浏览器即用，无需安装客户端

### 2.2 功能架构

│                     PaperPilot 工作台                      │

│  │ 知识库管理 │  │     对话与问答       │  │  文档管理     │  │
│  │          │  │                    │  │              │  │
│  │ · 新建库  │  │ · 多轮对话         │  │ · 上传 PDF   │  │
│  │ · 切换库  │  │ · 流式回答         │  │ · 索引状态   │  │

### 2.3 核心功能清单

| 功能 | 说明 |
|------|------|
| **账号系统** | 邮箱验证码注册 + 密码登录；JWT 令牌鉴权 |
| **多知识库** | 按课题自由创建、重命名、删除；提问时可勾选一个或多个库 |
| **PDF 上传与解析** | 支持带文字层 PDF 与扫描件（OCR）；自动解析、切分、建索引 |
| **基于文献的问答** | 只依据库内检索到的原文片段回答；引用标注文献名与页码 |
| **多文献对比** | 对比/共同点/差异类问题以表格对照呈现，覆盖所有相关文献 |
| **连续对话** | 会话可保存、切换，支持上下文指代（如「这篇」「上面那个」） |
| **分层长记忆** | 最近轮次 + 滚动摘要 + 相关旧对话召回；可按会话关闭和清除 |
| **科研 Skill** | 论文问答、单篇精读、多文献综述、观点核查和证据约束写作；自动路由或手动选择 |
| **AI 用量账本** | 按用户、文档、会话、Skill、模型和操作记录 Token 与价格快照 |
| **流式输出** | 回答实时逐字流出，大段回答阅读体验更顺畅 |
| **日配额管理** | 每用户每日提问与上传上限，防止资源滥用 |

## 三、AI 原生能力

PaperPilot 不是在传统应用上「加了一层 AI」，而是以 AI 为核心管线驱动全流程。

### 3.1 四层 PDF 解析栈

| 层级 | 能力 | 技术 |
|------|------|------|
| **L0 文本提取** | 从 PDF 提取可选中文字 | PyMuPDF + pypdf |
| **L1 视觉路由** | 图表密集页自动调用多模态模型描述 | 智谱 GLM-4V-Flash |
| **L2 OCR 兜底** | 扫描件 / 文字稀少页走 OCR | RapidOCR（纯 Python，无需 Tesseract） |
| **L3 结构还原** | 识别标题层级、章节归属，为后续检索提供结构线索 | 规则 + 启发式 |

### 3.2 混合检索（Hybrid Retrieval）

| 模块 | 作用 |
|------|------|
| **语义向量检索** | 基于智谱 embedding-3 向量化 + pgvector 近邻搜索 |
| **BM25 稀疏检索** | 关键词级召回补充，CJK 双字母分词 + 拉丁分词 |
| **RRF 融合** | Reciprocal Rank Fusion 合并两路结果 |
| **LLM 重排** | 用大模型对融合结果做相关性打分，筛选最终 Top-K 送入生成 |

### 3.3 意图识别与多文献覆盖

系统基于规则自动分类用户意图：

- **清单查询**（catalog）：「库里有哪些论文」→ 直接返回文献列表，不触发检索
- **对比查询**（compare）：「两篇共同点和差异」→ 确保所有相关文献都参与检索与回答
- **证据问答**（qa）：默认路径，检索 → 生成 → 引用

### 3.4 证据边界与拒答机制

这是 PaperPilot 最核心的 AI 设计原则：

1. **回答必须有据**：事实、数据、结论必须能在检索到的原文片段中找到依据
2. **禁止外部补全**：不得用训练记忆、常识或推测补充文献未写明的内容
3. **坦诚不足**：证据为空或不足时，明确说明缺什么，允许部分回答
4. **引用可溯**：关键结论旁标注文献名与页码，引文为原文子串

### 3.5 上下文感知生成

| 特性 | 说明 |
|------|------|
| **文献分组 Context** | 检索结果按文献分组注入 Prompt，避免模型混淆来源 |
| **文献 Context 卡片** | 为每篇文档维护入库摘要快照，辅助对比类问题时的兜底信息 |
| **对话历史注入** | 最近 N 轮对话作为上下文，支持「这篇」「上面那个」等指代 |
| **独立问题改写** | 先把含指代的追问改写为独立检索问题，并校验原问题语义未丢失 |
| **滚动摘要与情景记忆** | 较早轮次分批压缩，按相关性、时近性和重要性召回 |
| **排版策略** | 普通问答用自然段落；对比类问题强制输出 Markdown 表格 |

### 3.6 Agent 工具调用

对于复杂问题，系统可启用 Agent 模式（最多 4 轮工具调用），调用检索工具获取更多证据后再生成最终回答。

## 四、技术架构与落地可行性

### 4.1 系统架构

```
用户浏览器
    │  HTTPS (Nginx)
    ▼
┌─────────────────────────────────────────────┐
│           FastAPI API 层（Python）              │
│                                             │
│  Auth · Libraries · Documents · Query       │
│  Conversations · Health · Quotas            │
│  Query: Hybrid → Rerank → LLM Generate     │
└──────────────────┬──────────────────────────┘
                   │
          持久化索引任务队列
                   │
                   ▼
       ┌──────────────────────┐
       │ 独立 Worker           │
       │ PDF 解析/OCR/Vision   │
       │ 切分/Embedding/索引   │
       └──────────┬───────────┘
                  │
        ┌─────────┼──────────┐
        ▼         ▼          ▼
  ┌──────────┐ ┌─────┐ ┌──────────┐
  │ Postgres │ │ PDF │ │ 外部 API │
  │ pgvector │ │ 存储 │ │DeepSeek  │
  │ pg_trgm  │ │     │ │ 智谱     │
  └──────────┘ └─────┘ └──────────┘
```

### 4.2 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 后端框架 | FastAPI | 异步、类型安全、生态成熟 |
| 数据库 | PostgreSQL + pgvector | 关系数据与向量检索统一；省运维 |
| 聊天模型 | DeepSeek（可配置） | 国内延迟低、性价比高 |
| 向量模型 | 智谱 embedding-3（1024 维） | 中文质量稳定、OpenAI 兼容接口 |
| 多模态 | 智谱 GLM-4V-Flash | 图表描述，与 embedding 同账号 |
| OCR | RapidOCR | 纯 Python、免 Tesseract 安装 |
| 部署 | Docker Compose | 一键启动 API + Worker + 数据库 |
| 反代 & HTTPS | Nginx + Let's Encrypt | 生产级 TLS 终结 |

### 4.3 安全与隔离

| 措施 | 说明 |
|------|------|
| JWT 鉴权 | 强制 ≥24 位随机 Secret；弱 Secret 拒绝启动 |
| 账号隔离 | 所有 API 查询均带 `owner_id` 过滤，库/文档/对话按用户隔离 |
| CORS 白名单 | 生产环境仅允许指定域名 |
| IP 限流 | 注册发码、上传、查询均有 IP 级速率限制 |
| 日配额 | 每用户每日 80 次提问 / 20 次上传，防止资源滥用 |
| 邮箱验证 | 注册需真实邮箱验证码，防机器批量注册 |

### 4.4 可靠性

| 机制 | 说明 |
|------|------|
| 索引自动恢复 | 持久化任务、租约续期、Worker 崩溃后回收并重新入队 |
| 失败重试 | 指数退避重试，区分可重试与永久失败 |
| 数据库迁移 | Alembic 版本管理，平滑升级 |
| 健康检查 | Worker 心跳、队列积压、最老等待时间及近一小时成功/失败数 |
| 备份脚本 | PostgreSQL dump + PDF + SHA-256 清单 + 表计数成套备份 |

### 4.5 部署现状

- **生产环境**：阿里云 ECS（Ubuntu 22.04），Docker Compose 运行
- **域名**：paperpilot.xin，Nginx 反代 + Let's Encrypt HTTPS
- **更新流程**：成套备份并校验 → Alembic 迁移 → 重建 API/Worker → 健康与存储审计 → 灰度开放

## 五、商业化思考

### 5.1 商业模式分析

| 模式 | 说明 | 适合阶段 |
|------|------|----------|
| **免费公测** | 开放注册，日配额限制使用量 | 当前阶段：积累用户与反馈 |
| **Freemium** | 基础免费 + 高级功能付费（更大配额、优先队列、高级模型） | 用户量达千级 |
| **实验室订阅** | 按课题组/实验室收费，提供管理员后台与数据导出 | 机构采购 |
| **私有化部署** | 为有合规需求的机构提供本地部署方案 | 企业/医院等 |

### 5.2 竞品对比

| 维度 | PaperPilot | 通用 AI 助手（ChatGPT 等） | 企业知识库（Notion AI 等） |
|------|-----------|--------------------------|-------------------------|
| 文献专属 | 专为 PDF 论文设计 | 通用，无文献管理 | 通用知识管理 |
| 证据可信度 | 严格原文引用，拒答机制 | 可能编造内容 | 依赖文档质量 |
| 多库隔离 | 按课题建库 | 无 | 有但功能重 |
| 部署门槛 | Docker 一键部署 | SaaS 依赖 | SaaS 或重量级私有化 |
| 成本 | 按实际 Token、模型价格版本和功能路径核算 | 订阅制 | 订阅制 |
| 中文优化 | 中文分词、中文模型 | 通用 | 通用 |

## 六、总结

PaperPilot 抓住了个人科研工作者「论文多、翻找难、对比累」的真实痛点，以「私人文献知识库 + AI 原文问答」的形态，提供了一个比通用 AI 更可信、比企业知识库更轻量的解决方案。

**核心竞争力**在于：
1. **证据边界机制**——不编、不猜、不补，回答可溯源到原文页码
2. **四层解析 + 混合检索**——从扫描件到图表、从关键词到语义，最大化文献理解
3. **极简部署与使用**——浏览器打开即用，Docker 一键自建

当前处于公测阶段，以免费 + 日配额方式运营；后续可沿 Freemium → 实验室订阅 → 私有化部署路径实现商业化。
